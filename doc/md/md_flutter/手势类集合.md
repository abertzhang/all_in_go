### <u>类GestureRecognizer</u>

[官方文档](https://api.flutter.dev/flutter/gestures/GestureRecognizer-class.html)

`GestureRecognizer` 是 `手势检测器` 的顶层抽象，且继承自 `GestureArenaMember`，标志着其族系的类都具有`参加竞技的资格`。 另外，该类中并未实现 `GestureArenaMember` 的两个抽象方法，也就说明这两个方法会在子类中被实现，处理相关逻辑。

他作为一个`顶层抽象类`，只是对成员进行定义、逻辑进行整合，并没有什么实质性的操作，所以本身并不复杂。至于那些具体的逻辑将会被具体的子类去处理，这便是`由抽象到具体`的过程，可以根据不同的需求去分化出不同的具体实现，将一个抽象演化为一个族系，有着`个性`的同时，也存有本质的`共性`，使这便是求同存异。

#### 源码解析

```dart
/*
debugOwner 是一个 Object? 对象，表示识别器的所有者，从名字也能看出，它只是 debug 辅助属性，在 toString 方法及 debugFillProperties 中有所使用，可以方便地标识识别器。比如在 GestureDetector 源码中，创建 TapGestureRecognizer 对象时将 debugOwner 设置为 this。
_kindFilter 的类型是 PointerDeviceKind 枚举，在之前有所介绍，有如下五个元素。根据名称可以知道，该属性用于触点类型的过滤，可以限定识别器的特定类型，如果为 null ，则全部指针事件都将被识别。
_pointerToKind 是一个的映射表，用于保存指针 id 和指针设备类型之间的映射。该成员默认为 {}，会随着该类的行为进行维护。
*/
final Object? debugOwner;
final PointerDeviceKind? _kindFilter;
final Map<int, PointerDeviceKind> _pointerToKind = <int, PointerDeviceKind>{};
GestureRecognizer({ this.debugOwner, PointerDeviceKind? kind }) : _kindFilter = kind;
```

<img src="https://p3-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/7f3663f75d4341ff9d98e272a0269e9c~tplv-k3u1fbpfcp-zoom-in-crop-mark:3024:0:0:0.awebp" alt="img" style="zoom:50%;" />

`addPointer` 方法的逻辑，其主要作用就是将`触点数据`注册到 `手势检测器` 中。

`isPointerAllowed` 方法用于校验`该识别器`是否允许跟踪指针。这里处理逻辑很简单：如果 `_kindFilter` 为空，则表示允许；否则 `event.kind` 需要和`_kindFilter` 一致才可以允许，从这也体现出`_kindFilter`的具体价值。另外需要注意该方法上有 `@protected`，表示这里只是最基本的校验逻辑，子类是可以重写的。

当 `isPointerAllowed` 方法被允许时，会执行 `addAllowedPointer` 对 `event` 正式进行注册。否则，将触发 `handleNonAllowedPointer` 方法，拒绝该次触点。这两个方法在 `GestureRecognizer` 中都是空实现，将由子类进行覆写实现。这就是很常见的 `模板方法设计模式`。`GestureRecognizer` 中只是定义了整体逻辑执行的`骨架`，并不关心具体实现的细节。这些细节将由具体的子类进行具体的处理。

#### 单击事件

```dart
onTap: 	      void Function();
onTapCancel:  void Function();
onTapDown:    void Function(TapDownDetails details);
onTapUp:      void Function(TapUpDetails details);
```

首先触发 `onTapDown` 回调，回调函数中可以得到 `TapDownDetails` 对象，获取触点信息。

然后抬起手时触发 `onTapUp` 回调， 回调函数中可以得到 `TapUpDetails` 对象，获取触点信息。

最后回调 `onTap `函数，表示一次单击事件的触发。

另外，当触发了`onTapDown` ，但并未完成单击事件时，会触发 `onTapCancel` 事件。

例如，按下后，产生了滑动，再抬起手的场合。 要注意：单击取消的场合，按下时依然会触发 `onTapDown`，但是不会触发 `onTapUp` 和 `onTap`。

#### 双击事件

```dart
onDoubleTap:  		void Function();
onDoubleTapDown: 	void Function(TapDownDetails details);
onDoubleTapCancel:	void Function();
```

普通双击时，onDoubleTapDown` 先触发，可以回调触点信息，然后回调 `onDoubleTap。

当触发了`onDoubleTapDown` ，但并未完成双击事件时，会触发 `onDoubleTapCancel`。例如，双击的第二次未抬起，发生了移动的场合。要注意：双击取消的场合，按下时依然会触发 `onDoubleTapDown`。

#### 长按事件

```
onLongPressStart:       void Function(LongPressStartDetails details);
onLongPress: 	        void Function();
onLongPressMoveUpdate:  void Function(LongPressMoveUpdateDetails details);
onLongPressEnd:		void Function(LongPressEndDetails details);
onLongPressUp:		void Function();
```

首先 `onLongPressStart` 触发，回调开始触点信息；

然后 `onLongPress` 触发；

随着触点的移动，会不断触发 `onLongPressMoveUpdate`，回调移动触点信息；

最后抬手时，先触发 `onLongPressEnd`，回调结束触点信息；

接着触发 `onLongPressUp` 标志着一次长按事件的完成。

#### 平移事件 Pan

```
onPanDown: 	void Function(DragDownDetails details);
onPanStart: 	void Function(DragStartDetails details);
onPanUpdate:  	void Function(DragUpdateDetails details);
onPanEnd:	void Function(DragEndDetails details);
onPanCancel:	void Function();
```

首先 `onPanDown` 触发，回调按下触点信息；

然后 `onPanStart` 触发，回调开始拖动的触点信息；

随着触点的移动，会不断触发 `onPanUpdate`，回调移动触点信息；

最后抬手时，触发 `onPanUpdate`，回调结束触点信息，标志着一次平移事件的完成。

<img src="https://p3-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/b192617e246e4a95a8b76f1f15d65a18~tplv-k3u1fbpfcp-zoom-in-crop-mark:3024:0:0:0.awebp" alt="img" style="zoom:67%;" />

还有一个 `onPanCancel` 回调函数，这个回调触发的时机是：当触发了 `onPanDown` 但未完成时触发。这个条件比较苛刻，一般出现在嵌套手势中，比如 `ListView` 本身可以响应下滑的事件，如果此时蓝色 `Container` 也可以响应事件，那么触点在蓝色 `Container` 上时，会触发 `onPanDown`，但当手势是下滑时， `ListView` 组件内容向下滑动，那么蓝色的 `Container` 此次的 `Pan` 事件就会被取消，而触发 `onPanCancel`。

#### 水平或竖直平移

`HorizontalDrag` 和 `VerticalDrag` 可以看作是 `Pan` 事件在水平和竖直方向的使用。它们回调的信息对象都是一致的，使用使用方法差不多。当只要处理`水平方向`的事件时，可以使用 `HorizontalDrag` 相关回调；只要处理`竖直方向`的事件时，可以使用 `VerticalDrag` 相关回调；

<img src="https://p3-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/62d1619437c146f4a7d1858674a2f0ef~tplv-k3u1fbpfcp-zoom-in-crop-mark:3024:0:0:0.awebp" alt="img" style="zoom:67%;" />

 `Horizontal` 和 `VerticalDrag` 相关的回调不可以同时使用，可以通过 `pan` 相关回调来处理。毕竟手势既可以横向，又可以竖向，就是普通的移动而已。

####  缩放事件 Scale

```
onScaleStart: 	void Function(ScaleStartDetails details);
onScaleUpdate: 	void Function(ScaleUpdateDetails details);
onScaleEnd:  	void Function(ScaleEndDetails details);
```

首先 `onScaleStart` 触发，回调按下触点信息；

然后随着触点的移动，会不断触发 `onScaleUpdate`，回调移动触点信息；

最后抬手时，触发 `onScaleEnd`，回调结束触点信息。

 `pan` 和 `scale` 相关的回调不能同时使用，因为`scale` 是 `pan` 的超集。也就是说，`pan` 可以做到的，`scale` 都可以做到。

#### 尝试裁决

通过名字也能猜出，这个裁决方法并不一定能判定胜负，只是去尝试裁决。会执行尝试的方向有下面三个:

- 【1】该竞技场人数为 1，会触发 `_resolveByDefault`，使竞技结束。
- 【2】该竞技场人数为 0，直接移除竞技场，使竞技结束。
- 【3】有内定的获胜者，会通过 `_resolveInFavorOf` 吹黑哨，使竞技结束。

除此之外的情况，竞技会继续进行。前面提到，在竞技场关闭时，会执行 `_tryToResolveArena` 尝试裁决。

<img src="https://p3-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/4898e11a1b7943d5b86a5c9189b47e06~tplv-k3u1fbpfcp-zoom-in-crop-mark:3024:0:0:0.awebp" alt="img" style="zoom:50%;" />

```dart
void _tryToResolveArena(int pointer, _GestureArena state) {
  assert(_arenas[pointer] == state);
  assert(!state.isOpen);
  if (state.members.length == 1) {
    scheduleMicrotask(() => _resolveByDefault(pointer, state));
  } else if (state.members.isEmpty) {
    _arenas.remove(pointer);
    assert(_debugLogDiagnostic(pointer, 'Arena empty.'));
  } else if (state.eagerWinner != null) {
    assert(_debugLogDiagnostic(pointer, 'Eager winner: ${state.eagerWinner}'));
    _resolveInFavorOf(pointer, state, state.eagerWinner!);
  }
}
```

#### 执行裁决

<img src="https://p3-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/7aec36f88e6842e7ad0fd31bba988ae1~tplv-k3u1fbpfcp-zoom-in-crop-mark:3024:0:0:0.awebp" alt="img" style="zoom: 33%;" />

```dart
void _resolve(int pointer, GestureArenaMember member, GestureDisposition disposition) {
  final _GestureArena? state = _arenas[pointer];
  if (state == null)
    return; // This arena has already resolved.
  if (disposition == GestureDisposition.rejected) {
    state.members.remove(member);
    member.rejectGesture(pointer);
    if (!state.isOpen)
      _tryToResolveArena(pointer, state);
  } else {
    if (state.isOpen) {
      state.eagerWinner ??= member;
    } else {
      _resolveInFavorOf(pointer, state, member);
    }
  }
}
```
